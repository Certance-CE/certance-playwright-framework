# Certance Lens — Claude Code project conventions

Read [AGENTS.md](../AGENTS.md) first. It is the single instruction file for AI agents
in this repo: the four lanes, the enforced rules, the constraints of the application
under test, and what to run before opening a pull request. This file adds only what is
specific to Claude Code and its subagents.

## The subagents

`.claude/agents/playwright-test-{planner,generator,healer}.md` are **Playwright's own
agents**, generated by `npx playwright init-agents` and committed **pristine** so they
stay in sync with upstream. `npm run agents:sync` regenerates them and fails if they
have drifted, so the fork can never silently lose the `browser_verify_*` grounding
loop the way a hand-edited copy did before.

**Do not hand-edit the agent files.** Project rules belong here or in `AGENTS.md`, never
inside a generated agent definition — a rule written into the file would be reverted by
the next `agents:sync`, and a governance edit there would make the drift check lie.

The generator verifies every locator against the **live DOM** (the `browser_verify_*`
tools) before it writes the test. A locator that was not grounded that way is not
acceptable — that grounding is the whole reason the agent is trusted to write code.

## The pipeline this framework runs

```
requirements/*.md  →  @req:-tagged Gherkin (features/)  →  step definitions + Page
Objects  →  run  →  a graded coverage matrix (npm run coverage:requirements)
```

The **front** of that pipeline (an external source or a requirement doc → a tagged
scenario) is the [`source-to-requirements`](../.github/agents/source-to-requirements.agent.md)
and [`requirements-to-bdd`](../.github/agents/requirements-to-bdd.agent.md) briefs; the
**generation** half (a scenario → verified Page Objects and steps against the live app)
is the subagents above. A test only grades `covered` when it passed **and** its bound
steps actually assert something — a green test that proves nothing grades `structural`.

## Golden rules (enforced — see [docs/GOLDEN_RULES.md](../docs/GOLDEN_RULES.md))

Nine of the twelve are lint-enforced, and a generated test that breaks one fails
`npm run lint`. In short: locators are `getByRole` / `getByLabel` / `getByTestId`, never
CSS or XPath; all UI interaction lives in Page Objects; assertions are web-first (no
`waitForTimeout`); test data is synthetic only, never real PII.

## The gate the agents work under

An agent **proposes**; a human **disposes**. Before a generated or healed test is
merged, the review asks one question: **would this test fail if the behaviour broke?**
The healer may replace a locator that drifted with an equal-or-stronger one, but must
**never weaken, skip, or `fixme` a test to make it pass** — a real regression is
surfaced as a finding, not silenced. That discipline is the point of the framework, and
what it is sold on.
